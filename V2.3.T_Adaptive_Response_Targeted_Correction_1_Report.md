## Confirmed reversal causes

Two narrow, independent state-carryover defects were found.  The correction
changes no preset or public parameter.

1. **Pattern-73 safety-settling carryover.**  Safety cancellation zeroed stale
   lead promptly, but the new authority path retained the pre-cancel estimator
   velocity and acceleration.  A later held-source report could therefore
   reopen old-direction lead from too large a state value.  The OLD path
   attenuated that dynamic state while settling; the NEW path did not.
   The correction applies the same bounded attenuation only when both
   `safetyCancellation` and `settling` are true.  Normal settling and a
   confirmed reversal are untouched.

2. **Persona directional ownership.**  Before a reversal reached its existing
   travel threshold, ordinary post-estimator ownership could change
   `m_motionDirection` to the estimator sign.  The next opposite source report
   then reset the accumulated evidence rather than completing the detector.
   The correction retains the prior direction only when there are at least two
   opposite reports and travel has reached 80% of the existing relevant
   threshold.  Small opposite jitter and normal coherent motion retain the old
   update path.

The ownership threshold calculation is deferred until there is actual
opposite-direction evidence.  This is mathematically equivalent to the prior
corrected Boolean expression and is the only production hot-path optimization.
