or Phase 2.  It ran only deterministic/offline tests against recorded traces;
it makes no claim of rendered-UI, physical-HOTAS, or user acceptance.

**Primary classification: PRODUCT BEHAVIOR VALID — HARNESS/CLASSIFIER DEFECT.**

**PATTERN-73 HARNESS/CLASSIFIER DEFECT — CORRECT TEST INFRASTRUCTURE BEFORE PHASE 2**

reviewed, accepted, and represented in the official verification evidence.

All times below are seconds from the deterministic scenario start.  `lead` is
the final production predictor lead, so a zero value means output follows the
physical source sample directly.

| Time | Source / physical observation | Frozen processor state | Output consequence |
| --- | --- | --- | --- |
| `.300` | continuing positive delta `+.0080000` | forward trend; 30 ms horizon | `lead=+.0625193` |
| `.304` | first new negative delta `-.0003198` | opposite evidence 1, soft travel `.0003198`; stale-lead safety cancellation | `lead=0` |
| `.308` | second new negative delta `-.0003200` | evidence 2, soft travel `.0006397`, still below `.03` full-reversal threshold | `lead=0` |
| `.416` | held source sample (not a new device update) | one interpolated report temporarily retains forward trend | `lead=+.0128796` for one 4 ms report |
| `.552` | slow negative leg continues | cancellation remains active; full reversal not yet qualified | `lead=0` |
| `.572` | accumulated opposing travel `.0287627` | still below `.03` threshold | `lead=0` |
| `.576` | accumulated opposing travel `.0308427` | full soft reversal and opposite predictor lead qualify | `lead=-.0000863` |
| `.580` | continuing negative movement | full reversal remains active | `lead=-.0002503` |

The exact terminology matters:

1. **True underlying reversal time:** `.300`, when the authored human
   trajectory changes from the outgoing positive ramp to a negative derivative.
2. **First source-visible / first mapper-visible reversal sample:** `.304`.
   The first actual physical delta is negative; a source update and mapper
   report occur at that instant.
3. **Canonical two-sample device observation time:** approximately `.308`.
   This is the frozen harness event time (two coherent opposed samples), not
   the first time the predictor becomes safe.
4. **Stale-lead cancellation time:** `.304`, one source/mapper period after the
   derivative change.  `safetyCancellation` forces zero horizon immediately.
5. **Full predictor reversal / opposite-lead reacquisition:** `.576`, 268 ms
   after the frozen harness's `.308` event.  This is a deliberately stricter
   trend-classification threshold, not the first safe output response.

The original 180 ms timer expires at `.488` (`.308 + .180`).  It cleared the
pending event before the internal full detector became true at `.576`; the
harness subsequently recorded the detector as a "false reversal."  The raw
`reacquisition=-1` sentinel in the original result is therefore an expired
harness event, not evidence that the production output continued to lead in
the wrong direction.

## 4. Processor mechanics, sample holds, and the triggering rule

At 250 Hz, the relevant frozen full-reversal threshold is
`max(0.012 * 2.5, 0.075 * 0.004 * 1.25) = 0.03` opposing travel.  The first
negative sample is only about `.00032`; the slow `.300–.550` segment cannot
reach `.03` quickly.  The full detector is consequently correct to wait for
coherent opposing travel, while the independent safety rule is correct to
remove stale forward lead on the very first opposite raw sample.

There is one 4 ms held-source report at `.416`.  It briefly produced a forward
lead before the next actual source update reasserted cancellation.  This is a
sample-and-hold/interpolation artifact, not a missing hardware observation.
Across the `.304–.576` interval there are 68 mapper reports and only that one
positive wrong-direction lead report.

The old classifier triggered because the event both carried a substantive
human reversal (`|human velocity| >= .075`) and missed its 180 ms **full
detector** deadline.  It did not ask whether the processor had already
cancelled stale lead promptly, how long any remaining wrong-direction lead
lasted, or whether the input was the unusual slow-drift construction above.

The test-only correction preserves the raw event but maps it to `HARNESS` only
when all of the following are demonstrated:

- stale lead is cancelled within one source/mapper period plus 0.5 ms;
- the measured wrong-direction lead area is at most `.0001`; and
- the existing input/reversal predicates remain present.

All other original Product-Suspect paths are retained.  This makes a late full
detector still visible as a sentinel without mistaking it for a user-visible
or production safety failure.

## 6. Neighbor and boundary comparison

The closest frozen control scenarios distinguish the mechanism:

| Scenario | First full detector / output result | Classifier outcome |
| --- | --- | --- |
| Pattern 70 | detector `.444`, 36 ms after device event | passes |
| Pattern 71 | detector `.444`, 36 ms after device event | passes |
| Pattern 72 | detector at its device event; opposite lead by `.092` | passes |
| Pattern 69 / false bait | no true reversal event | passes |
| Pattern 73 | safety cancellation `.304`; full detector `.576` | old false-positive suspect |

Patterns 70 and 71 provide a much stronger initial reverse excursion (about
`1.25` versus Pattern-73's `.08` slow leg), so they satisfy the `.03` travel
criterion within the old deadline.  Pattern 73 is not a generic failure to
handle reversals; it is the narrow case where a weak real negative derivative
is intentionally treated as insufficient for a full trend flip while output
safety is already active.

Boundary probes support that causal explanation:

- Initial reverse velocities `.04` through `.20` still cross the full detector
  after the old `.488` deadline, although stale lead is cancelled immediately.
- At `.30`, the full detector occurs at `.472`, before the deadline, and the
  old classifier passes.
- Moving only source/mapper alignment by one sample shifts observed-event time
  (`.304`, `.308`, `.312`) but leaves full detector at `.576`; the underlying
  mechanism does not change.
- Deliberate 125 Hz and 60 Hz source holds delay *new physical evidence* and
  make the bounded area larger (`.002424` and `.00352014`).  These are not
  silently reclassified by the correction, and retain their value as cadence
  sensitivity probes.

## 8. User-visible consequence and root cause

The production output follows the physical value from `.304` onward; it does
not carry its previous forward predictor horizon through the slow reversal.
There is one short held-sample forward lead, bounded as described above.  This
is not established as a perceptible physical issue: no live controller, game,
or rendered UI test was performed, and the recorded corpus contains no
matching slow-dwell trace.  What is established is the model-level safety
property: stale predictive lead is cancelled on the first source-visible
opposite sample.

Root cause: the validation classifier equated a late internal full-reversal
telemetry event with a late safe output response.  Frozen production behavior
has two separate stages—immediate stale-lead cancellation and later coherent
trend reacquisition.  Pattern 73 forces them far apart, and the 180 ms
classifier deadline measured the latter while ignoring the former.  Once the
deadline cleared the event, the later legitimate detector transition was
misreported as a false reversal.

## 9. Classification and requested decision

This is category **B**: `PRODUCT BEHAVIOR VALID — HARNESS/CLASSIFIER DEFECT`.
No production modification is justified.  In particular, lowering the frozen
full-reversal travel threshold would trade intentional noise resistance for a
test expectation and is not supported by the evidence.

The only proposed correction is test infrastructure: retain the raw finding,
but classify it as `HARNESS` when prompt stale-lead cancellation and the
negligible-area bound are both measured.  This correction was exercised in a
targeted normal-harness canonical reversal subset:

| Canonical reversal subset | 66 scenario runs, 21,241 samples, 0 hard failures |
| Raw behavior rows | 18 retained |
| Product-Suspect category after correction | 0 |

| Adaptive smoke | 143 runs, 86,636 samples, 0 hard / 0 behavioral failures |

The Phase 1 Monster output-envelope findings are not erased or re-scored by
this result: its existing `2,480 beneficial / 975 benign / 746 harmful`

finding-classification issue.  A future full canonical refresh, after the
test-only fix is accepted, would be expected to move these 18 rows from the
Product-Suspect bucket to the Harness bucket; that full refresh was deliberately
not run here.

**May Phase 2 proceed unchanged? No.**  Accept and formally rerun the test-only
classification correction first; then reconsider Phase 2 with the corrected
evidence.  There is no production repair, merge, release, deployment,
installation, or Phase 2 execution in this investigation.
