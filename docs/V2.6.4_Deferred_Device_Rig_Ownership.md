# V2.6.4 Deferred Device Rig Ownership Migration

## V2.6.3 boundary

V2.6.3 is a reliability hotfix. It repairs the post-HidHide controller
reconnect and reacquisition lifecycle, refreshes inventory, RigStatus, and
activation after that lifecycle, scopes vJoy repair to the selected Rig's
primary output, and keeps Flight Deck readiness bound to committed activation
state.

It deliberately does not change Signal Flow persistence or runtime semantics.

## Remaining architectural issue

Profiles still retain some runtime Rig and hardware authority. Fully removing
that authority requires the logical-member migration across mapping,
Automation, portability, and Signal Flow.

That work is V2.6.4 scope. It must establish this separation:

```text
Device Rig = hardware topology
Profile = behavior only
Activation policy = separate relationship layer
```

The migration must preserve existing mappings, curves, Adaptive Response,
buttons, POVs, Automation, Signal Flow topology, categories, and game rules
while changing concrete controller/output references into logical Rig-member
and output-role references. It must not be backported into V2.6.3 as a
side-effect of this reliability hotfix.
