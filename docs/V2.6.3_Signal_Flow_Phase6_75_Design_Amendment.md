# HOTAS BF6 Simple v2.6.3 Signal Flow — Phase 6.75 design amendment

## Scope

This amendment refines workspace interaction only. It does not alter canonical
routes, processor configuration, mixer semantics, revision-checked commands,
Undo/Redo, focused-editor ownership, compilation, or the DirectInput to vJoy
HOTPATH.

## Decisions

1. Inspector is one movable, non-modal workspace surface. It represents the
   currently inspected port, route, block, processor, mixer, note, or section;
   changing selection replaces its presentation content rather than creating
   an inspector-local settings model.
2. Ports are first-class inspectable objects. Their connection count and
   topology are derived from the canonical graph projection at selection time.
3. Text Note and Group / Section are bounded workspace annotations. They have
   no ports, canonical topology identity, runtime meaning, or compiler input.
   A target attachment is a stable presentation reference and never changes a
   route. Missing targets detach without deleting user text.
4. Port visibility is a workspace policy: `smart`, `connected`, `compact`, or
   `expanded`. Persisted explicit group state outranks temporary task reveal,
   which outranks the automatic policy.
5. Library processor insertion remains segment-targeted. It is offered only
   for canonical processor kinds supplied by the backend; an empty-canvas drop
   cannot invent an unattached processor instance.

## Extension boundary

Phase 7 global search/filters/learn, Phase 8 continuous telemetry, and Phase
9 semantic zoom/bundles remain out of scope. This phase may expose existing
workspace controls and authoritative deep links, but does not duplicate their
state or add report-rate work.
