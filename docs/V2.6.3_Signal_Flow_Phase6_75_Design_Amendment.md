# HOTAS BF6 Simple — Signal Flow Graphical Editor — Phase 6.75 design amendment

The historical filename preserves the application release lineage. The product
surface is named **Signal Flow Graphical Editor**, without a version label.

## Scope

This amendment refines workspace interaction only. It does not alter canonical
routes, processor configuration, mixer semantics, revision-checked commands,
Undo/Redo, focused-editor ownership, compilation, or the DirectInput to vJoy
HOTPATH.

## Decisions

1. Inspector is one movable, non-modal workspace surface. It represents the
   currently inspected port, route, block, processor, mixer, note, or section;
   changing selection replaces its presentation content rather than creating
   an inspector-local settings model.
2. Ports are first-class inspectable objects. Their connection count and
   topology are derived from the canonical graph projection at selection time.
3. Text Note and Group / Section are bounded workspace annotations. They have
   no ports, canonical topology identity, runtime meaning, or compiler input.
   A target attachment is a stable presentation reference and never changes a
   route. Missing targets detach without deleting user text.
4. Port visibility is a workspace policy: `smart`, `connected`, `compact`, or
   `expanded`. Persisted explicit group state outranks temporary task reveal,
   which outranks the automatic policy.
5. Library processor insertion remains segment-targeted. It is offered only
   for canonical processor kinds supplied by the backend; an empty-canvas drop
   cannot invent an unattached processor instance.

## Current implementation mapping

The graphical editor keeps its interaction state separate from canonical graph
state. `presentationIndex` is rebuilt only for a graph revision/source change;
port lookup, route lookup, hover, selection, pan, zoom, card drag, and wire
hit-testing consume that projection rather than rescanning the graph. The
settled-wire canvas remains beneath cards, so unrelated wires are occluded by
their card surfaces while a route's own endpoint cap remains visible at its
socket.

The workspace policy is explicit and persisted: the clickable **Ports: ...**
control selects `smart`, `connected`, `compact`, or `expanded`; the inspector,
library, and graph settings are floating workspace surfaces; and viewport
pan/zoom writes use the existing workspace acknowledgement path. Temporary
section reveal and processor-channel dwell both use an 1100 ms grace period.
The processor preview adds a visible pending input/output pair, then performs
the existing revision-checked canonical share operation only after the dwell
completes.

The Block Library maintains one retained presentation model for its delegates.
Arming, dragging, cancelling, placing, or inserting never removes an entry
from that catalog. A processor release is accepted only on a compatible,
highlighted canonical segment; node and annotation entries take their own
presentation-only placement paths. This keeps the source tile stable and
prevents a failed release from leaving a detached visual card behind.

Notes and groups remain workspace-only annotations. Their move path provides a
node/route snap preview with hysteresis; release persists an existing
attachment reference, while a missing attachment reports as detached rather
than deleting the annotation.

## Extension boundary

Phase 7 global search/filters/learn, Phase 8 continuous telemetry, and Phase
9 semantic zoom/bundles remain out of scope. This phase may expose existing
workspace controls and authoritative deep links, but does not duplicate their
state or add report-rate work.
