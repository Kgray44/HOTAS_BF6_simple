## Delivered control-plane seam

`HidHideHealthService` projects typed dimensions, stable `HIDHIDE_` App Health findings, activities, repairability, context generation, and copyable evidence without replacing `ControllerReadinessService`, Setup Truth, Setup Repair, or `AppHealthService`.

The lightweight Essential check is coalesced and never probes the driver directly. A user-requested Full Check runs off the GUI thread, permits one scan at a time, queues a second Full Check behind the first, and discards results whose Device Rig/controller/output/executable context is stale.

`hidhide_read_only_protocol` opens only `\\.\HidHide` with `GENERIC_READ` and uses only the documented `GET_ACTIVE`, `GET_INVERSE`, `GET_WHITELIST`, and `GET_BLACKLIST` IOCTLs. It has bounded overlapped waits and preserves each native failure. No HidHide SET operation, helper invocation, driver/package installation, service change, or repair transaction was added.

The only repair routes presented are existing production authorities: mapper-only allowlisting for a proven mapper-exemption fault, or the existing Controller Readiness transaction after exact identity revalidation. Physical identity, managed virtual-output identity, incomplete inspection, recovery waits, and API/package/driver concerns do not gain a new mutation path.

## Presentation and safety boundaries

Overview, Devices, Diagnostics, and Flight Deck all consume the same `hidhideHealth` snapshot. Legacy and Standard Diagnostics now expose Full Check, Review Repair, and Copy Evidence; Flight Deck surfaces add detailed GET evidence and optional Doctor handoff. Health observation remains outside `MappingWorker`, DirectInput report handling, vJoy per-report output, Adaptive Response, and profile-control code.

The Doctor handoff writes only a sanitized local JSON summary (version/build, Device Rig ID, finding IDs, dimension states) and Doctor must independently revalidate all context. It does not include local executable paths, HID instance IDs, user profile data, raw driver output, or a repair instruction.
