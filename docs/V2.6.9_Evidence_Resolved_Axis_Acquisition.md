# V2.6.9 evidence-resolved DirectInput acquisition

## V2.6.8 baseline reconstructed before implementation

At V2.6.8, DirectInput object enumeration reaches `enumObjectCallback` in
`mapping_worker.cpp` (and the read-only inventory equivalent in
`controller_discovery.cpp`).  Each `DIDEVICEOBJECTINSTANCEW` is converted to a
`NativeAxisDescriptor` by `describeDirectInputAxisObject()`.

The baseline resolver has two inputs:

1. `guidType` is converted to a standard semantic axis (`GUID_XAxis` through
   `GUID_RzAxis`) when possible.
2. `dwOfs` is converted to a `DIJOYSTATE2` field slot when possible.

The V2.6.8 implementation then performs the following coupled decision:

```text
canonicalAxis     = semantic GUID, otherwise offset slot
formattedSource   = semantic GUID, otherwise offset slot
```

It records a contradiction when both inputs exist and differ, but the known
semantic GUID remains both the identity and the formatted source.  This was a
correct repair for the Saitek pedal evidence but not a general source resolver.

The descriptors are passed to `compileRuntimeAxisAcquisitions()`.  The compiler
creates a fixed primitive `RuntimeAxisAcquisition` for every target canonical
axis.  The DirectInput hot path reads only `binding.sourceIndex`, normalizes the
value, and places it in `PhysicalInputReport.axes[canonicalAxis]`.

Buffered object events are configured at acquisition.  V2.6.8 matches an event
to a descriptor by `dwOfs`; if a buffered object value diverges from the
currently compiled standard field, the worker keeps using the buffered object
value for that acquired session.  A bounded UI/control-plane tick persists that
fact as `acquisitionMethod = buffered`.  It does not resolve and persist a
replacement fixed `DIJOYSTATE2` field.

Descriptors, their native signature, ranges, manual overrides, and the
buffered-method observation are persisted inside the exact verified controller
record.  Controller identity matching prefers HID container identity, then HID
instance identity, DirectInput instance identity, and only then compatible
product/capability evidence.  On reconnect the worker re-enumerates native
objects and recompiles the runtime table; V2.6.8 does not independently
revalidate a persisted formatted-source relationship.

## Physical contradiction evidence

The physical Saitek Pro Flight Rudder Pedals show:

```text
native identity: GUID_RzAxis / Z Rotation
reported offset: DIJOFS_Z
live state field: DIJOYSTATE2::lRz
```

The physical T.Flight HOTAS One shows:

```text
native X identity: GUID_XAxis / X Axis
reported offset: DIJOFS_Y
live state field: DIJOYSTATE2::lY

native Y identity: GUID_YAxis / Y Axis
reported offset: DIJOFS_X
live state field: DIJOYSTATE2::lX
```

These facts establish the V2.6.9 rule:

```text
native semantic identity answers WHAT an object is
evidence-resolved formatted source answers WHERE its value is stored
```

Neither a semantic GUID nor `dwOfs` alone may be treated as universal proof of
the other fact.

## V2.6.9 design and safety boundary

V2.6.9 splits those two decisions and preserves GUID-first canonical identity.
`NativeAxisDescriptor::canonicalAxis` answers what a native object is;
`formattedSource` answers which scalar member of `DIJOYSTATE2` the fixed report
loop reads for that object.

At enumeration, the initial source evidence is intentionally conservative:

| Condition | Canonical identity | Initial state source | Verification state |
| --- | --- | --- | --- |
| Standard GUID and reported offset agree | semantic GUID | that shared field | verified metadata agreement |
| Standard GUID and reported offset disagree | semantic GUID | reported field candidate | not verified until native-event correlation |
| No unique semantic GUID | reported offset | reported field | verified offset fallback |
| Reused generic semantic GUID collision | the unique object in the semantic slot remains semantic; duplicates move to their own offset slots | matching fixed field | verified collision fallback |

A user-selected `AxisAcquisitionOverride` remains the highest-priority manual
choice.  It is compiled only when its exact native object signature still
matches.  Otherwise, on reconnect, a previously verified automatic source is
reused only when *all* of the following remain unchanged: canonical target,
semantic GUID, DirectInput type, reported offset, DirectInput instance, and
relative/absolute flag.  A changed descriptor starts over from the conservative
enumeration rule; no source proof is transferable merely because the controller
has a similar name or product identity.

Buffered events are bounded corroboration, not a permanent alternate transport.
When an unverified reported-field candidate receives a **freshly queued**
native object event, the worker compares that event against every fixed
`DIJOYSTATE2` member.  Only one normalized match is enough to promote the
matching member to `BufferedObjectCorrelation`; an equal-value or otherwise
ambiguous sample intentionally proves nothing.  This bounded eight-field
correlation runs only for the newly queued object event, never on an ordinary
poll.  A unique match verifies the candidate even when it already agrees with
the provisional read (the T.Flight case); a unique match can also replace a
contradictory candidate (the Saitek case).  The GUI control-plane tick persists
the uniquely correlated field and asks the worker to recompile the fixed
bindings.  Subsequent reports therefore use the verified scalar state field
directly.  An uncorroborated mismatch remains the existing buffered safety
fallback, and that fallback too is restored only for the matching native
signature after a reconnect.  Restoring the fallback does not freeze it
forever: matching later reports can still promote it to a verified fixed field
through the same correlation rule.

The resolved source remains a fixed `RuntimeAxisAcquisition::sourceIndex`.
Discovery, revalidation, evidence matching, persistence, and diagnostics stay
outside the DirectInput-to-mapping-to-vJoy report path.

## V2.6.9 qualification

- `mapping_core_tests` covers semantic/offset agreement, the physical Saitek
  Rz-versus-Z contradiction, the T.Flight X/Y cross-field proof and reconnect
  reuse, stale-signature rejection, configuration persistence, and duplicate
  generic semantic GUID enumeration in both orders.
- `app_backend_startup_tests` covers the identify/apply completion state and
  raw-acquisition presentation telemetry.  `app_qml_startup_tests` loads and
  navigates the native Flight Deck presentation with the evidence panel.
- `ui_release_contract_tests` asserts the release-level UI contract for source
  evidence, raw telemetry, and closing the identify dialog only after a source
  actually applies.
- The synthetic post-poll report-path benchmark includes the verified X/Y
  cross-field binding.  It records zero hot-path allocations; it measures
  neither DirectInput driver calls nor vJoy calls.
