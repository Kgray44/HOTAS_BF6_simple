# HOTAS BF6 v1.8.0 — Automation Engine

## Runtime boundary

Automation definitions are durable configuration data. A configuration update validates and compiles the complete rule set into a fixed-capacity immutable `CompiledAutomationSet`, then swaps that set with the existing compiled profile cache before the mapping worker observes it. The worker evaluates no QML, strings, JSON, settings, filesystem, network, or curve compilation per input report.

The hard limits are 64 rules, four conditions per rule, and four actions per rule. Invalid saved rules remain available for repair but do not enter the active compiled rule table. A globally impossible clamp intersection rejects publication of Automation effects entirely.

## Evaluation order

Each physical report is processed in this order:

1. Read one physical input snapshot and apply physical Button/POV profile controls.
2. Capture normalized physical axes, physical buttons/POV, base profile, and the resulting pre-Automation effective profile.
3. Evaluate Automation conditions once against that snapshot.
4. Feed active Automation profile Hold/Toggle contributions into the same profile override precedence engine as physical controls.
5. Resolve the final effective profile and evaluate its already-compiled axis curves.
6. Apply Automation axis actions, aggregate mapped and Automation vJoy buttons, and publish vJoy output.

Conditions cannot read another Automation's output, profile contribution, or modified axis result from the same cycle. Rules that combine an Effective Profile condition with a Profile action are rejected rather than solved iteratively.

## Conditions and hysteresis

Supported conditions are Always; Axis Above, Below, Between, and Outside Range; Button Held and Released; POV direction Active and Inactive; Base Profile Is; and Effective Profile Is.

Axis thresholds use latches. Above activates strictly above its threshold and remains active through `threshold - hysteresis`; Below is symmetric. Between activates within its range and remains active until below `minimum - hysteresis` or above `maximum + hysteresis`. Outside Range uses the opposite expanded boundaries while active. This is state hysteresis only; it does not introduce an intentional timing delay.

## Actions and resolution

Supported actions are vJoy Button Hold/Toggle, Profile Hold/Toggle, Axis Scale, Axis Offset, Axis Clamp, Axis Override Constant, Axis Mix, and Axis Follow. Toggle actions act only on the rule's false-to-true edge.

For each target physical axis, active actions resolve in this stable order:

1. base final-profile output;
2. highest-priority active Follow or Override (equal priority: earlier persisted rule order);
3. all active Scales multiply;
4. all Mix contributions add;
5. all Offsets add;
6. active Clamps intersect;
7. final output clamps to the legal normalized domain.

Axis Mix accepts Physical (normalized after calibration) or Processed (final-profile, pre-Automation) source stages. Self-mix is rejected. vJoy buttons aggregate as an OR of ordinary mapping, POV mapping, Automation Hold, and Automation Toggle contributors.

Profile Holds and Toggles share one precedence system: most-recent active Hold, then most-recent active Toggle, then manual/base profile. Automation state is cleared on Stop Mapping, controller disconnect, runtime configuration swap, and master disable.

## Persistence and migration

Schema 11 adds `automationEnabled` and global `automations[]`. Each rule persists stable ID, name, enabled state, ALL/ANY mode, priority, conditions, and actions. v1.7/schema-10 configurations load with Automation enabled and an empty rule list, preserving existing behavior. Toggle latches are runtime-only and never persist.

## Diagnostics and performance

The UI exposes engine status, rule/active counts, per-rule state and health, and separate Automation evaluation microseconds. The synthetic hot-path benchmark includes 0, 8, 32, and 64-rule cases and records typical/p95/p99/worst latency, throughput, and allocation count. It uses production compiled records and enables allocation instrumentation only around report evaluation.
