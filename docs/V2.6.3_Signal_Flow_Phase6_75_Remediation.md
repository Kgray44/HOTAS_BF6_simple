## Owner-rejection response

This candidate responds to the rejected Inspector/Library workspace by making
the ordinary native UI the first path to every reviewable function. It retains
the approved Phase 6 performance-recovery baseline: all routing, topology,
processor insertion, validation, undo, and persistence remain in the existing
canonical backend commands. The presentation changes do not create graph-local
devices, ports, routes, processors, mappings, or runtime state.

## Corrected workspace behaviour

- **Inspector:** a floating, non-modal, draggable, Esc-closeable surface whose
  size follows content up to a scrollable cap. Its unselected state gives useful
  guidance. Port, route, device/output, processor/mixer, and annotation
  selections now project identity, topology, processing, state, contextual
  actions, and an opt-in technical disclosure from canonical graph data.
- **Section disclosure:** every card group has a visible independent control.
  Persistent manual state wins over temporary task/hover reveal, which wins
  over the selected visibility policy. Each section now owns a small local
  state machine (`COLLAPSED`, `TEMP_OPEN`, `TEMP_OPEN_GRACE`): its full
  rendered header-and-ports region stays open while occupied and for five
  seconds after pointer exit. The state and timer are per section, never per
  port; an active card drag freezes disclosure geometry and defers the local
  incident-route reflow until release. Smart and Connected views retain linked
  endpoints as compact rows while hiding only unused ports.
- **Native menus:** right clicks now belong to explicit right-button targets for
  node bodies, ports, routes, and empty canvas. The canvas offers Inspector,
  Block Library, Graph Settings, authoritative device/output setup, canonical
  processor insertion, notes, and groups. Node, port, and route menus offer
  relevant Inspect, disclosure, editor, processing, and annotation actions.
- **Library and command surface:** the two-row command surface makes
  Inspector, Block Library, Graph Settings, visibility, Fit, layout, and
  history visible without crowding context/profile controls. The Library names
  Inputs/Outputs, processor families, and Other, paints an insertion preview
  while dragging, and directs physical inputs/virtual outputs to the existing
  authoritative Devices workflow.
- **Notes and groups:** both are visibly available from Library and canvas.
  They remain presentation-only; notes can attach/detach from a block or route,
  and group move-contents remains an explicit presentation option.

## Owner-review addendum — canonical Block Library and hover grace

The prior Library bound its processor list to
`signalFlowAvailableProcessorsForSegment` for the first selected route
segment. That API is intentionally a *drop-target compatibility* query: it
filters for an exact real runtime stage and hides processor kinds already on
the source. With no current selected wire (or a route containing a processor),
the Library therefore incorrectly looked empty; searches such as `respo` could
not discover **Response Curve** even though canonical insertion supported it.

The Library now calls the independent backend catalog
`signalFlowProcessorCatalog`. It derives entries only from the real canonical
editable set: Response Curve, Deadzone, Center Hold, Invert, Output Limits,
and Adaptive Response. It does not advertise visual-only Mixer, OR, AND,
Toggle, Pulse, Gate, or POV blocks. Empty-query categories and case-insensitive
search operate over this catalog; `respo` finds Response Curve and `invert`
finds Invert regardless of the selected graph entity.

Arming a processor with Enter creates a placement ghost without inventing a
route target. Pointer movement queries the existing compatibility API only
against nearby painted, visible wire segments, with a small retained-target
hysteresis. The atomic canonical insertion command is called only after a
compatible segment is present. This preserves the compiled execution-stage
rules and the pre-existing no-fake-state contract.

The native focused qualification covers the rendered full-section pointer
path (header to revealed port row), independent simultaneous section states,
the five-second grace expiry, manual-open precedence, and the existing fast
click-to-drag disclosure freeze. It asserts that the hover transitions cause
no global wire-cache, hit-index, or canonical graph refresh; only affected
incident-route geometry may be refreshed after structural settling. It also
covers the native keyboard path from `respo` search through Enter-arming,
visible processor ghost, compatible-wire preview, and Escape cancellation.
