# V2.5.5 Flight Deck Device Rig management

V2.5.5 completes the Device Rig workflow in Flight Deck without creating a
theme-specific configuration model.

## What Flight Deck now supports

- Create a Device Rig from one or more physical controllers and a selected
  Virtual Output.
- Mark each member Required or Optional while creating the Rig and later in
  Rig Details.
- Inspect controller identity, connection, verification, and required/optional
  status; add or remove members; rename the Rig; and assign or manage outputs.
- Set a compatible Rig active through the existing coordinated
  Profile/Rig/Output activation command.
- Run the established setup and verification path for a Rig, and delete a Rig
  only after an explicit confirmation that explains affected Profile links.
- Open a Profile's assigned Rig directly in Flight Deck. Opening a Rig remains
  view/edit context only; it does not activate the Rig.

## Resolver and persistence boundary

Every operation uses the existing AppBackend Device Rig API and the same
configuration used by Devices, Profiles, Axes, Buttons, persistence,
import/export, diagnostics, and the V2.5.4 Activation Resolver. Required and
Optional semantics are evaluated by the backend: a missing Optional member can
reduce capability without disqualifying automatic selection, while a missing,
ambiguous, or unverified Required member remains a blocker.

Deleting a Rig uses the canonical delete path. Referencing Profiles have their
Rig assignment cleared; they are never silently redirected to an unrelated
Rig. The DirectInput -> MappingWorker -> vJoy report path remains unchanged.
