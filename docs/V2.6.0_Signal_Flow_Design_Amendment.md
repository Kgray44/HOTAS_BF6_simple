# V2.6.0 Signal Flow Design Amendment — Five-Theme Scope

**Status:** Governing V2.6.0 amendment
**Date:** 2026-09-11
**Applies to:** Signal Flow implementation, qualification, release evidence, and all related documentation

## Purpose and traceability

This amendment is authorized by the V2.6.0 Signal Flow implementation goal. It updates only the theme scope in the supplied governing design documents without weakening or replacing any other requirement:

- `HOTAS_BF6_Signal_Flow_Master_Design_Specification_v1.1.md` — Design Freeze v1.1
- `HOTAS_BF6_Signal_Flow_Invariant_Sheet_v1.1.md` — Design Freeze v1.1

The V2.6.0 goal is the controlling authorization for this amendment. All unamended requirements in those v1.1 documents remain in force.

## Amendment

Every Signal Flow reference to support for **four themes** is amended to require support for these **five current HOTAS BF6 themes**:

1. Legacy
2. Standard
3. Top Gun
4. Day Ops
5. Flight Deck

This includes, without limitation:

- Master Specification §28 (`SF-THEME-001` through `SF-THEME-003`)
- Master Specification §32 theme-test requirements (`SF-TEST-007`)
- Master Specification §33 Phase 10 theme qualification
- Master Specification §36 Feature Completion Criterion 23
- Invariant Sheet I-40
- Invariant Sheet Phase Exit Checklist
- all campaign-level visual, accessibility, motion, stress, and release qualification requirements

## Flight Deck requirement

Flight Deck is a mature presentation experience, not a palette variant. Signal Flow for Flight Deck must use the same canonical Signal Flow semantics and backend as the other themes while presenting a genuinely native Flight Deck workspace. It must not be implemented by recoloring Standard, wrapping generic graph components in dark rectangles, or applying superficial aviation decoration.

The implementation must study and reuse the current Flight Deck shell, spacing, controls, navigation, surfaces, light/dark behavior where supported, and interaction conventions. Flight Deck visual polish is a first-class V2.6.0 release gate and receives dedicated native visual review.

## No other change

This amendment does not relax canonical-model, identity, HOTPATH, transaction, accessibility, migration, test, or release requirements. Where the v1.1 documents use four-theme wording, the amended five-theme wording is stricter and controls.
