# HOTAS BF6 v1.4 Curve Studio engineering report

Status: Release build and live-device smoke verification completed. The full
per-family physical-motion matrix remains explicitly open; it has not been
fabricated from synthetic results.

## Correctness and configuration

- J is a continuous one-sided progressive curve: `u^p`, where
  `p = 1 + 1.80s`. Centered J remaps `[-1,1]` through `[0,1]` and back. Its
  intentional non-neutral virtual output at physical neutral is surfaced by
  Curve Health and Signal Path.
- Centered S is the required mirrored progressive response:
  `sign(x) * |x|^p`. Unipolar S uses a strength-blended smoothstep that keeps
  `0`, `50%`, and `100%` fixed.
- Response Strength is continuous for every family. Advanced, Personal, and
  Custom use `F(x,s)=(1-s)x+sA(x)`; all resulting shapes compile into the
  immutable 4097-sample LUT before the worker accepts configuration.
- Schema 7 migrates pre-amendment Advanced/Personal/point curves to `100%`
  strength, preserving their former full-response behavior.
- The axis reset defect was the worker/UI fallback which rewrote the selected
  axis when a DirectInput object was unavailable. Selection is now durable
  editor state. Personal selection now enters Personal mode, selects a
  compatible saved preset when available, or preserves an unsaved editable
  Personal response when the library is empty.

## Curve Studio UI

- The selector header uses graphite controls, stable geometry, current
  profile/axis context, a universal strength slider, and all six families:
  Linear, J-Curve, S-Curve, Advanced, Personal, and Custom.
- The graph is a recessed avionics-style instrument with a dark canvas,
  bounded grid, cursor inspection, preview chip, wheel zoom, middle-drag pan,
  and empty-space left-drag pan. Point dragging remains reserved for points.
- Point Editing is a dedicated card with exact Input/Output numeric controls,
  symmetry, interpolation, density, snapping, add/remove, and locking.
  Point and empty-graph right-click menus expose only valid contextual actions.
- View/History groups Frame Curve, Reset Display, Undo, and Redo. Reset
  Display clears only viewport/cursor/comparison/preview state; it never
  changes the active response definition.
- Response Characteristics and Signal Path are permanent cards. Every dashed
  overlay has an owner: comparison, preview, or optional effective response.
- Curve Studio now uses the same shared aviation-panel surface as the accepted
  Buttons page. Its selectors, dark checkboxes/toggles, buttons, fields, and
  dialogs share the readable graphite/cyan control language.
- The editor is page-scrollable with intrinsic card heights and three
  responsive compositions: wide multi-column, medium two-column, and narrow
  one-column. The header reduces to two selector columns at narrow widths,
  while Response Strength retains its own full-width row and the graph keeps a
  350 px minimum preferred height.

## Presets and research

`docs/curve-research.md` records corrected equations, source links, evaluator

## Performance implementation and evidence

- The report path reads only a precompiled immutable LUT. Configuration
  compilation was moved out of the mapping worker and installed as a prepared
  runtime mapping at the configuration boundary.
- The dedicated mapper worker starts at Qt `HighPriority`, deliberately below
  time-critical priority, so a busy Curve Studio yields to physical report
  handling without starving normal rendering or system work.
- On startup and explicit HidHide refresh, a cloaked installation checks and,
  when needed, registers only the current mapper executable path. This avoids
  a rebuilt Release folder being invisibly excluded from HidHide's allowlist.
- DirectInput acquisition, polling, and state-read failures now release the
  stale device immediately, mark the physical snapshot disconnected, and
  force fresh attached-device discovery. Mapping intent remains enabled, so
  vJoy is automatically reacquired after a reconnect.
- The UI distinguishes requested mapping from acquired output during that
  recovery window: it shows **MAPPING PAUSED - RECONNECTING** and keeps the
  action as **STOP MAPPING**, preventing a misleading start action from
  canceling automatic recovery.
- The worker records a fixed rolling window of 2,048 completed physical-report
  latencies. A GUI-side timer snapshots it for p95/p99 at most four times per
  second; the report loop only stores one already-measured latency sample and
  never allocates, sorts, or analyses it.
- The benchmark exercises production axis transform, physical monitor, button
  routing, atomics, change detection, and LUT evaluation. It covers Linear,
  high-strength J, high-strength S, Advanced, Shooter/Flight-derived,
  Personal, and 25-point Custom under idle and UI-model stress. It deliberately
  excludes DirectInput and vJoy driver calls when no real device is attached.
- The worker remains change-driven for vJoy outputs: identical stationary
  reports produce no additional axis/button write decisions after initial
  publication.

### Release hot-path benchmark

The current Release executable ran on this 16-logical-CPU machine. Each case
uses the production immutable 4097-sample LUT, production transform/button/
change-detection logic, and fixed-slot latency telemetry. It is deliberately a
synthetic report-to-output-decision benchmark: it does not claim DirectInput
cadence or vJoy driver-call timing.

| Curve | Synthetic reports/sec | Typical µs | p95 µs | p99 µs | Worst µs |
| --- | ---: | ---: | ---: | ---: | ---: |
| Linear | 4,326,967 | 0.2 | 0.3 | 0.3 | 191.7 |
| J-Curve | 4,244,491 | 0.2 | 0.3 | 0.4 | 166.6 |
| S-Curve | 4,282,261 | 0.2 | 0.3 | 0.4 | 63.0 |
| Advanced: Precision Tracking | 4,449,685 | 0.2 | 0.3 | 0.3 | 53.5 |
| Custom: 25 point | 4,215,212 | 0.2 | 0.3 | 0.3 | 13.6 |

All cases counted zero heap allocations in the measured report loop. Repeated
stationary reports made `0.000` additional vJoy write decisions per report.

### Live DirectInput/vJoy verification

With a connected T.Flight Hotas One, vJoy Device 1 ready, mapping active, and
the current Custom response (S-Curve basis, 50% strength), the Diagnostics
page observed a real report cadence of 200 Hz while the editor was exercised
with pan/zoom, comparison browsing, preset browsing, page scrolling, and five
reversible point drags (each immediately undone). The worker telemetry,
covering DirectInput `Poll` and `GetDeviceState`, transform/LUT work, and
change-driven vJoy output, read: current 11 µs, p95 25 µs, p99 42 µs, average
13 µs, and lifetime peak 409 µs. vJoy reported `0/s` while the physical
controls were stationary, which is the intended idle/change-driven behavior.

This validates the real device path under active editor UI without a material
throughput or percentile regression. It does not claim moving-control writes
or a separate physical measurement for every curve family; those require a
short explicit physical-motion pass before a release tag.
