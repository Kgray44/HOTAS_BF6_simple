# V2.6.6 Axis Acquisition Qualification Record

## Previous V2.6.3 limitation

V2.6.3 established a deterministic canonical identity map from DirectInput
`dwOfs` to `PhysicalAxis` and retained native descriptor metadata. Its runtime
reader nevertheless assumed that the enumerated object delivered data through
the matching fixed `DIJOYSTATE2` field (`lX`, `lY`, `lZ`, `lRx`, `lRy`, `lRz`,
or a slider). The synthetic sentinels proved that the switch reads `lRz` for
the canonical Rz slot. They did not prove that a real controller's enumerated
`Z Rotation` object supplies changing values through `lRz`.

Therefore V2.6.3 covered canonical field selection, not real-hardware
acquisition-channel qualification. It must not be used as evidence that the
Saitek Pro Flight Rudder Pedals Z Rotation defect was fixed.

## Candidate model

The V2.6.6 candidate records these independent states per physical axis:

- **Discovered:** a native DirectInput axis object exists.
- **Acquisition source resolved:** a compiled DirectInput offset has been
  associated with the canonical axis and an actual native range has been read.
- **Live verified:** a meaningful change was observed after initial sampling.

Read-only discovery captures object enumeration index, native name, GUID type,
`dwType`, `dwOfs`, DirectInput instance, relative/absolute classification, and
the reported native range. It does not request a range or require the user to
move every control. Normal mapper acquisition requests `-10000..10000`, records
the `SetProperty` HRESULT, reads the actual range back, and normalizes against
the observed span rather than assuming every driver accepted the request.

The report path uses precompiled fixed values only. It reads the descriptor's
offset, normalizes the raw value, and writes a canonical slot. DirectInput
buffered object data is configured once at acquisition time. When a buffered
event for that exact object contradicts the standard state field, that axis
uses the buffered source for the session and the UI control plane persists the
evidence for the exact selected controller. No GUID parsing, QString work,
allocation, HID enumeration, or setup query is introduced per input report.

## Current evidence boundary

The candidate includes deterministic coverage for scrambled offsets, all
standard DIJOYSTATE2 slots, unsigned and one-sided observed ranges, invalid
range fallback, and persisted acquisition metadata. It does not contain actual
Saitek EnumObjects output, buffered-event traces, HID value-capability output,
or physical controller acceptance.

Physical qualification remains required on the exact candidate with the
owner's Saitek Pro Flight Rudder Pedals: individually move both toe brakes and
the center Z Rotation control; verify the correct HOTAS BF6 meter and mapped
vJoy output; then reconnect the pedals and restart HOTAS BF6. Until that gate
passes, the defect status is **not fixed**.
