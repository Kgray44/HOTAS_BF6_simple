# v2.6.4 — Adaptive Response Activation Hotfix

> Candidate status: this document describes the local owner-review candidate.
> It is not evidence of a protected-main merge, tag, installer, signed asset,
> public release, or physical controller-to-vJoy acceptance.

## What changed

Adaptive Response now separates response selection from activation. Light,
Balanced, Fast, Aggressive, and Extreme remain selectable response templates;
the enabled setting is the only state that activates prediction.

- Choosing a response keeps the layer's existing enabled ownership and value.
  A disabled response remains selected and reviewable instead of being replaced
  by an OFF pseudo-preset.
- The same rule applies across Global, Category, Profile, and Device layers.
  Custom presets and Automation response actions configure response behavior;
  they do not turn prediction on or off.
- Flight Deck and Standard surfaces show the resolved inherited response while
  preserving the raw layer ownership, so an inherited selection remains visible
  when its explicit enabled state is disabled.

## Configuration compatibility

Schema 33 first materializes the activation behavior that v2.6.3 real presets
previously supplied implicitly at their owning layer. Legacy `off` preset
values then normalize to the Balanced response with explicit disabled
activation. The normalization covers saved configuration, portable profiles
and categories, custom preset payloads, and old Automation preset actions. It
preserves the chosen configuration while removing the obsolete activation side
effect; no unrelated controller, Device Rig, HidHide, Signal Flow, or mapper
hot-path behavior is changed.

## Candidate qualification

Focused core, Automation, QML release-contract, and isolated Flight Deck
lifecycle tests cover explicit activation, legacy migration, inherited response
display, response selection, and preview behavior. Native owner review remains
required before any merge or release decision.
