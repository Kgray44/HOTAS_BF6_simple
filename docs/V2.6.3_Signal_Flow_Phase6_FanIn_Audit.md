## Accepted Phase 5 model audit

Phase 5 supplies durable route and processor identity, persisted
route-qualified segments, revision-checked snapshot commands, stale-history
rejection, focused-editor reconciliation, a rendered-port geometry cache, and
a fixed bounded runtime compiler.  Its source-owned processor ordering is
truthful: domain, deadzone, center hold, invert, curve, output limits,
Adaptive Response, then an explicit mixer.

The received `SignalFlowMixer` is already a canonical processor record, but it
only carries scope, destination axis, mode, and enabled state.  Its contributor
set is inferred from every direct route that happens to target that destination.
The mixer input ports are consequently route-qualified projections rather than
durable mixer-owned inputs, and there is no single durable mixer-output edge.
The initial Default Connections implementation likewise uses positional
axis-to-axis matching and a small flattened change list.

## Decision: central canonical extension is required

**No.** The accepted Phase 5 model cannot represent a true multi-input
processor without graph-only or inferred side state.  Phase 6 will extend the
canonical `SignalFlowMixer` centrally and minimally with:

- durable input records referencing the participating canonical route identity
  and owning a stable input-port identity;
- one durable mixer output-port identity;
- canonical validation that every active analog contributor is explicitly
  represented by the mixer and no hidden contributor can survive;
- graph projection built from those canonical input/output identities;
- compilation that remains bounded and allocation-free per report.

The extension deliberately retains the existing route records as the canonical
source-to-destination compatibility and focused-editor projection.  A mixer
now names exactly which of those route records it combines; it does not leave
membership to route enumeration or QML.  The graph will show one source-to-
mixer-input edge per input and one mixer-output-to-destination edge.

## Phase 6 semantics selected for implementation

The Phase 5 runtime already supports three bounded, deterministic modes.  This
phase will retain that vetted catalog rather than expose an unimplemented mode:

- **Average:** arithmetic mean of available enabled inputs; unavailable inputs
  do not contribute.
- **Sum Clamped:** sum all available enabled inputs, clamped to the normalized
  output range.
- **Highest Magnitude:** select the available input with the greatest absolute
  normalized magnitude; equal magnitude resolves by durable mixer-input order.

`Last Active`, weighted, and priority modes remain unavailable until their
runtime activity/fallback semantics can be specified and exercised without
HOTPATH regression.  Button fan-in remains the existing explicit canonical OR
endpoint behavior; Phase 6 does not introduce a speculative button processor.

## Transaction and preview boundaries

Mixer create/grow/remove and collision replacement will use one
revision-checked `SignalFlowCommand` snapshot transaction.  A Default
Connections preview is advisory only; applying it rechecks the exact captured
revision, validates the complete proposed topology, persists once, compiles
once, and produces one undo entry.  An external canonical mutation therefore
invalidates an open preview rather than allowing a stale overwrite.

No Phase 7 Search/Learn work, merge, tag, or release is authorized by this
phase.

## Implemented Phase 6 canonical topology

`SignalFlowMixer` now owns a bounded ordered list of `SignalFlowMixerInput`
records. Each record names the exact canonical route identity that participates
and a durable mixer input-port id; the mixer also owns its durable output-port
id. Phase 5 mixers without those fields are deterministically backfilled once
from their already active scoped axis routes, then saved in the new explicit
form. Malformed, duplicated, unrelated, or inactive inputs are rejected during
canonical reconciliation. A route that merely happens to share a destination
is disabled unless it is named by the active mixer.

Graph segments now project one source-to-mixer-input edge for every named
input and precisely one mixer-output-to-destination edge, carried by the first
durable mixer input. This is a graph projection of persisted topology, not a
QML convention. Profile portability remaps named input route identities and
regenerates local port identity when importing a profile.

The qualified `Average`, `Sum Clamped`, and `Highest Magnitude` modes remain
the only exposed selection. The graph's mixer editor changes a mode under the
current revision, removes one named input by disconnecting that source route,
or removes the mixer by explicitly disconnecting all of its named inputs. No
operation guesses a surviving direct route.

## Implemented Default Connections plan

The preview now produces a deterministic row-level plan with canonical axis
pairing or a unique configured-alias pairing. It categorizes planned changes,
preserved existing routes, inactive-axis exclusions, occupied-destination
collisions, and alias/destination ambiguities. Connect Unassigned Only never
overwrites an existing source route. Replace All is blocked until ambiguities
are deliberately resolved and then applies the complete reviewed plan as one
revision-checked command and one undo entry. Both Standard and Flight Deck
present the same categorized preview and call the same backend transaction.
